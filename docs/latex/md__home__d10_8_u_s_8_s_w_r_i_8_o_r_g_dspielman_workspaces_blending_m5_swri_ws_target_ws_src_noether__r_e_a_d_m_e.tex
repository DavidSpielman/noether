This repository provides software for performing tool path planning on arbitrary mesh surfaces. We define tool path planning as the generation of an ordered set of waypoints for a robotic process (e.\+g., painting, sanding, inspection, routing, etc.) based on some input geometry. The idea is that the tool of the robot should traverse through this set of waypoints in order to accomplish the desired task.

We think of the tool path planning process as a pipeline consisting of 3 steps\+:
\begin{DoxyEnumerate}
\item Mesh modification
\begin{DoxyItemize}
\item Often input geometry (specifically meshes) does not actually reflect the surface from which we want to generate tool paths. Usually we want to process the mesh in various ways, such as smoothing, segmentation, or primitive fitting and projection.
\end{DoxyItemize}
\end{DoxyEnumerate}
\begin{DoxyEnumerate}
\item Tool path planning
\begin{DoxyItemize}
\item This is the generation of waypoints directly from the modified mesh(es). Planners generally create waypoints directly on the surface of the input modified mesh(es).
\end{DoxyItemize}
\end{DoxyEnumerate}
\begin{DoxyEnumerate}
\item Tool path modification
\begin{DoxyItemize}
\item Many robot processes require application specific changes or additions to a tool path. These include operations like order reorganization, pose offsets, approaches/departures, etc. Instead of building these changes directly into customized tool path planners, we implement them as a separate step in the pipeline.
\end{DoxyItemize}
\end{DoxyEnumerate}\hypertarget{md__home__d10_8_u_s_8_s_w_r_i_8_o_r_g_dspielman_workspaces_blending_m5_swri_ws_target_ws_src_noether__r_e_a_d_m_e_autotoc_md11}{}\doxysection{G\+UI}\label{md__home__d10_8_u_s_8_s_w_r_i_8_o_r_g_dspielman_workspaces_blending_m5_swri_ws_target_ws_src_noether__r_e_a_d_m_e_autotoc_md11}
This project provides a G\+UI application for use of the provided tool path planning utilities. Load an arbitrary mesh, configure your desired tool path planning pipeline, and experiment with different types of planners and modifiers. The generated tool path can then be saved to a Y\+A\+ML file for use in other applications.

This repository provides three key abstract interfaces to facilitate the tool path planning pipeline\+:
\begin{DoxyItemize}
\item $\ast$$\ast$\href{noether_tpp/include/noether_tpp/core/mesh_modifier.h}{\texttt{ {\ttfamily Mesh\+Modifier}}}$\ast$$\ast$
\begin{DoxyItemize}
\item Takes an mesh and returns a vector of modified meshes
\item Implementation examples include primitive fitting and projection, region of interest selection, smoothing, hole filling, etc.
\end{DoxyItemize}
\item $\ast$$\ast$\href{noether_tpp/include/noether_tpp/core/tool_path_planner.h}{\texttt{ {\ttfamily Tool\+Path\+Planner}}}$\ast$$\ast$
\begin{DoxyItemize}
\item Takes an input mesh and produces a tool path
\item This repository also provides two sub-\/interfaces for planners with more specific behavior\+:
\begin{DoxyItemize}
\item \href{noether_tpp/include/noether_tpp/tool_path_planners/raster/raster_planner.h}{\texttt{ {\ttfamily Raster\+Planner}}}
\item \href{noether_tpp/include/noether_tpp/tool_path_planners/edge/edge_planner.h}{\texttt{ {\ttfamily Edge\+Planner}}}
\end{DoxyItemize}
\item Implementation examples include plane slice raster planner, C\+AM style planner, mesh half-\/edge planner
\end{DoxyItemize}
\item $\ast$$\ast$\href{noether_tpp/include/noether_tpp/core/tool_path_modifier.h}{\texttt{ {\ttfamily Tool\+Path\+Modifier}}}$\ast$$\ast$
\begin{DoxyItemize}
\item Takes an tool path and produces a modified tool path
\item Implementation examples include order reorganization, orientation smoothing, approach/departure addition, pose offset, etc.
\end{DoxyItemize}
\end{DoxyItemize}
